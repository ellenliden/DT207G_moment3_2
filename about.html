Om webbplatsen

Denna webbplats är en fristående frontend som använder Fetch API för att kommunicera med min webbtjänst från Moment 3 Steg 1 (moment3_2). Lösningen är byggd med ren HTML, CSS och JavaScript (utan ramverk) och visar ett komplett flöde: lista befintliga arbetserfarenheter, lägga till en ny arbetserfarenhet och radera en arbetserfarenhet via ett publikt REST-API.

Utvecklingsprocess: Jag använde grundstrukturen från moment 2.2 som bas och anpassade den för moment3_2 backend. Huvudsakliga ändringar var uppdatering av API-konfiguration, anpassning av formulärfält för MongoDB-schema och modifiering av JavaScript för att hantera arbetserfarenheter istället för användare.

  • Syfte: Bygga en oberoende frontend som konsumerar ett externt API (REST) och visar grundläggande CRUD-flöden (Create/Read/Delete) med tydlig felhantering.
  • Struktur: Tre sidor – startsida med lista över arbetserfarenheter, en "lägg till"-sida med formulär och denna sida som beskriver syfte, teknik och databas.
  • Teknik: HTML, CSS (responsiv med rem) och JavaScript.
  • Webbtjänst (API): dt207g-moment3-rf1t.onrender.com
  • API-endpoint: /api/experiences
  • Databas-server: MongoDB (via webbtjänsten). Backend exponerar REST-endpoints för arbetserfarenheter och hanterar datalagring, validering och statuskoder.

Slutsatser

Arbetet har tydliggjort flera viktiga aspekter av webbutveckling:

  • CORS: När frontend och backend ligger på olika domäner/portar krävs att servern tillåter kors-origin-förfrågningar (CORS). I backend löses detta med cors-middleware.
  • HTTP-statuskoder och fel: Jag har byggt in felhantering i klienten (t.ex. visar statusmeddelanden vid 201/400/404/500) för att ge användaren förståelig feedback.
  • Fetch och JSON: Att sätta rätt headers (Content-Type: application/json), serialisera JSON vid POST/PUT och hantera svar beroende på innehållstyp är centralt för robusta anrop.
  • MongoDB ObjectId: Backend använder MongoDB med ObjectId för unika identifierare, vilket kräver specifik validering i API:et.
  • Datumvalidering: ISO8601-format för datum säkerställer korrekt dataöverföring mellan frontend och backend.
  • Modulär kod: Jag separerar API-anrop, listvy och formulärlogik i egna filer för bättre läsbarhet och underhåll.
  • Tillgänglighet och responsivitet: Jag använder semantiska element, tydliga statusmeddelanden och rem-baserade mått för att förbättra läsbarhet och responsiv design.
